# CLAUDE.md — правила разработки курса «Поехали!» (PyFlora)

Полное ТЗ: `PROMPT.md`. Мир, персонажи, словарь, стиль: `docs/world.md`. Факты о космонавтике: `docs/space-facts.md` (единственный источник). Текущее состояние: `CONTEXT.md` (обновлять в конце каждого этапа), решения: `docs/decisions.md`. Формат контента: `docs/content-schema.md`. Как вести урок: `docs/teacher-guide.md`; памятка студента: `docs/student-guide.md` (обновлять оба при изменении интерфейса).

## Главное
- Это КУРС, а не просто игра: ядро — учебная работа (ТЗ → код → тесты → отладка → сдача), игровой слой — оболочка.
- Урок ведёт преподаватель через «Пульт урока» (`/#/teacher`, сервер `server/bureau_server`). В синхронном режиме студент не проходит дальше этапа, не открытого преподавателем. Любая новая механика должна уважать допуск (`src/lib/gate.ts`: `stageAllowed`, `orderAllowed`, `effectiveStars`) и «Внимание!».
- Без сервера игра работает в режиме «Самостоятельно» (для экспертов и дома).
- Сначала информация, потом вопросы: смена не начинается с вопросов по новому материалу (тест A — после инструктажа, разминка — после напоминания на доске).
- «Конец смены» командный: экипаж собирает программу из частей (`content/crews`, узел `crew`, `game/CrewMission.tsx`); «Гонка экипажей» ранжирует только экипажи, очки считает сервер (`server/bureau_server/crews.py`).

## Язык
- Интерфейс, диалоги, контент, сообщения об ошибках, документация — на русском.
- Код, идентификаторы, имена файлов, коммиты — на английском.

## Архитектура (неизменные правила)
- Вся проверка кода студента — только в `packages/judge` (чистый Python 3.11+, без зависимостей). Тот же код работает в Pyodide (браузер) и CPython. В TS — только отображение и экономика для показа.
- Судья детерминирован: бесконечные циклы останавливает лимит строк (`sys.settrace`), а не время. Никакого `time`, глобального `random`, сети.
- Результаты судьи сериализуются `judge.to_json`; CPython и Pyodide должны давать побайтово одинаковый JSON (`npm run test:identity`).
- Скрытые кейсы не раскрывают ввод и ожидаемый вывод — только замечание заказчика (`complaint`).
- Код студента выполняется в Web Worker (Pyodide). Сервер урока код НЕ выполняет: серверная проверка — только отдельный изолированный сервис `checker` (Docker, `BUREAU_CHECKER_URL`; `BUREAU_LOCAL_CHECK=1` — лишь для разработки и тестов). Pyodide, шрифты, графика — только локально, без CDN.
- Сервер урока: FastAPI + WebSocket + SQLite (stdlib), без внешних сервисов; права проверяются на каждом эндпоинте и в WebSocket; ФИО не собираем (только псевдоним).
- Ввод, который набирает человек (код урока, псевдоним), считать «грязным»: нормализовать регистр, пробелы, дефисы, латиницу/кириллицу, ё/е (`server/bureau_server/codes.py`).
- Контент — данные (`content/*.json`), не код. Любое изменение контента должно проходить `python tools/lint_content.py` с 0 ошибок.
- Графика — собственные слоистые SVG (`frontend/src/art`, манифест `assets/manifest.json`) или CC0; источники — в `assets/LICENSES.md`. Никаких материалов чужих игр и логотипов реальных организаций.
- Помощник Вика — «интеллектуальная обучающая система на правилах». Не называть ИИ/LLM, не давать готовых решений в подсказках.

## Сеттинг и факты
- Бюро «Космос» и его люди вымышлены; реальные люди не произносят реплик. Реальные факты — только из `docs/space-facts.md` (новый факт — сначала туда, с источником), не больше одного факта на сцену.
- Словарь: заказчик, задание, испытания, запуск, премия, надёжность бюро, журнал миссий, пневмопочта (`docs/world.md` §3). Технические id (`orders`, `coins`, `tips`, `reviews`, `shop`, id локаций и хотспотов) не переименовывать.

## Правила контента (линтер)
- Реплика ≤ 35 слов, абзац ≤ 2 предложений, ≤ 1 нового термина `[[...]]` на реплику, ≤ 4 реплик подряд без проверки.
- `requires[]` — только навыки, введённые раньше (`introduces[]`); граф навыков без циклов.
- Эталон использует только `allowed_constructs` занятия, получает 5★, соблюдает PEP 8; шаблоны проваливают хотя бы один кейс; у скрытых кейсов есть `complaint` и `requirement_id`.
- Экспонаты `content/museum.json` ссылаются на id факта из `docs/space-facts.md`; у узла `launch` есть `craft`.
- Сюжетные тексты помечать `review_needed: true` и вносить в `docs/content-review.md`.

## Стиль кода
- Python: PEP 8, type hints, `from __future__ import annotations`. Сообщения для студента — по-русски, дружелюбно, формат «что случилось → где → что проверить».
- TypeScript: `strict`, без `any`, функциональные компоненты React, состояние игры — Zustand (`src/store.ts`), состояние урока — `src/lesson/lessonStore.ts`; чистая логика — в `src/lib` и `src/dialogue/engine.ts` с тестами Vitest.
- Цвета, отступы, радиусы, шрифты — только токены из `src/styles/tokens.css` (палитра «ретро-плакат»); рамки UI — `--line`, контуры иллюстраций — `--ink`, затемнение — `--scrim`, текст на акценте — `--on-accent`.

## Игра, а не сайт (обязательно)
- Никаких шапок, страниц и форм в игре: всё — сцены (`src/game/Stage`), диалоги (`DialogueBox`), выборы-реплики, панели «в мире», рабочий телефон и пауза по Esc. Исключения — служебные страницы `/#/teacher`, `/#/present`, `/#/plan/:n`, `/#/print/:n`, `/#/experts`, `/#/art`, `/#/checks`, `/#/style`.
- Теорию объясняют персонажи (Ольга у доски — `board`), реплики игрока — варианты выбора; новые функции открываются постепенно (`unlock`) с уведомлением.
- Новый контент — через сценарные узлы (`docs/content-schema.md`), не через новые экраны.

## UX (обязательно)
- Одна главная (primary) кнопка на экране; деструктивное — с подтверждением и отменой.
- Колонка чтения 560–680 px, текст ≥ 18 px, код ≥ 16 px, межстрочный ≥ 1.6, цели касания ≥ 44 px.
- Между соседними элементами и до края контейнера — зазор ≥ 1px через `gap`/`padding`; элементы в ряду выровнены, иконки и текст в кнопках центрированы.
- Анимации — `transform`/`opacity` (Framer Motion), без скачков layout; `prefers-reduced-motion` отключает их.
- Светлая и тёмная темы, A−/A+, «читаемый шрифт» (Lexend + Golos Text), режим «Классика» без игрового слоя. Не опираться только на цвет (✓/✗ + текст).
- Перед «готово» — проверка в браузере: светлая/тёмная тема, 360 px и десктоп, нет горизонтального скролла и пересечений (`getBoundingClientRect`); для урока — сценарий «пульт открывает этап → ученик продолжает».

## Тесты
- `python -m pytest -q packages/judge/tests tools/tests server/tests` — судья, линтер, реальный контент, сервер урока.
- `python tools/lint_content.py` — линтер контента.
- `cd frontend && node scripts/ui-audit.mjs http://localhost:8010 <пароль> <папка>` — аудит вёрстки всех экранов (темы, 360/десктоп, A+) со скриншотами; запускать перед «готово» после правок интерфейса.
- `cd frontend && npm test` — Vitest; `npm run build` — типы и сборка; `npm run test:identity` — CPython vs Pyodide; `npm run test:e2e` — Playwright (после сборки, установленный Chrome).

## Процесс
- Простые и объёмные задачи (контент по схеме, графика, компоненты по чёткому интерфейсу, тесты) делегировать субагентам более простых моделей (sonnet/haiku) с точным интерфейсом и обязательной самопроверкой.
- Перед крупной переделкой — короткий опрос пользователя.
- После каждого этапа обновлять `CONTEXT.md`.
