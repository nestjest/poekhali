# «Поехали!» — курс Python для новичков

Образовательная игра-курс для МДК 05.04 «Разработка приложений средствами языка Python». Игрок от первого лица приходит на первую работу в **Бюро «Космос»** — вымышленное конструкторское бюро малых спутников. Инструктор Ольга объясняет теорию у доски, наставник Вика и стажёр Макс разбирают практику. Заказчики (школьный кружок, ЦУП бюро…) выдают задания: игрок уточняет требования, пишет бортовую программу на Python, испытывает её на стенде и сдаёт. В конце смены аппарат запускают на орбиту. В репликах, задачах и «Музее бюро» — проверяемые факты о российской космонавтике.

Это **курс**: урок ведёт преподаватель через «Пульт урока». Он открывает этапы, и ученик не проходит дальше, пока этап не открыт. Ещё на пульте — «Внимание!», живая панель класса, зачёт заданий, код ученика с комментариями, опросы класса, проектор и отчёт урока (CSV).

**Попробовать онлайн:** https://poekhali.vercel.app/ — игра и сервер урока (Vercel + PostgreSQL): «Войти в урок» по коду, пульт преподавателя — https://poekhali.vercel.app/#/teacher (пароль выдаёт автор). Зеркало без сервера урока (только «Самостоятельно») — https://nestjest.github.io/poekhali/.

**Музей в работе.** Экспонаты «Музея бюро» нужно изучать: после принятого задания заказчик задаёт вопрос по экспонату (+10 премии), экипаж в конце смены проходит музейный опрос (очки в «Гонке экипажей»), а день завершается «Цитатой дня» — документальными словами Гагарина, Циолковского, Терешковой, Беляева с ФИО, годами и тем, чем человек занимался.

Объём: вводное занятие 0 и занятия 1–3 по 90 минут, плюс демонстрационное занятие 4 (коллекции, функции, файлы и библиотеки, классы, боты). Для школьников — режим «Знакомство» (занятия 0–1).

## Запуск на уроке

Нужны Node.js 20+ и Python 3.11+.

```bash
cd frontend && npm install && npm run build      # собрать игру
cd ../server && python -m pip install -r requirements.txt
python -m bureau_server                          # адреса и пароль преподавателя — в окне
```

Ученики открывают `http://<адрес>:8000/` → «Войти в урок» (код урока + псевдоним). Преподаватель — `http://<адрес>:8000/#/teacher`, проектор — кнопка «Проектор ↗» на пульте. Подробно — [руководство преподавателя](docs/teacher-guide.md) и [памятка студента](docs/student-guide.md).

### Через Docker (с серверной проверкой кода)

```bash
BUREAU_TEACHER_PASSWORD=придумайте-пароль docker compose up --build
```

Адрес для учеников внутри контейнера неизвестен: узнайте адрес компьютера (`ipconfig`) или задайте `BUREAU_PUBLIC_URL=http://<адрес>:8000` — его покажут окно запуска, пульт и проектор.

Поднимаются два сервиса: `app` (игра + сервер урока, порт 8000) и `checker` — изолированная проверка программ учеников по скрытым испытаниям с сервера (без выхода в сеть, файловая система только для чтения, без привилегий). Сам сервер урока код учеников не исполняет; без `checker` программы проверяет браузер ученика.

### Vercel: игра + сервер урока в облаке

Пульт урока работает и без своего компьютера-сервера: `vercel.json` раздаёт собранную игру, а `api/index.py` запускает сервер урока как serverless-функцию.
1. Импортируйте репозиторий в Vercel (или `npx vercel` в корне).
2. Storage → Create → **Neon (PostgreSQL)** → подключить к проекту: появится `DATABASE_URL`.
3. Settings → Environment Variables: `BUREAU_TEACHER_PASSWORD` — пароль преподавателя.
4. Redeploy. Ученики — `https://<проект>.vercel.app/` → «Войти в урок», преподаватель — `/#/teacher`.

Проверка развёрнутого сервера: `cd frontend && E2E_BASE_URL=https://<проект>.vercel.app E2E_PASSWORD=<пароль> npx playwright test` (тесты создают и закрывают учебные уроки).

Ограничения Vercel: нет WebSocket — игра и пульт обновляются опросом каждые 3 секунды; нет сервиса `checker` — программы проверяет браузер ученика (как без Docker). Для класса с проверкой скрытых испытаний на сервере используйте локальный запуск или Docker.

### Beget (виртуальный хостинг)

Игра и сервер урока на обычном хостинге Beget с Passenger (`deploy/beget`). В терминале хостинга (панель → «Терминал»):

```bash
git clone https://github.com/nestjest/poekhali ~/poekhali && bash ~/poekhali/deploy/beget/install.sh
```

Скрипт ставит Node.js в домашнюю папку и собирает игру, ставит пакеты Python в `~/poekhali/.pydeps`, кладёт игру в `public_html`, а `passenger_wsgi.py` — рядом с ней. При первом запуске он показывает пароль преподавателя. Настройки — `~/poekhali-data/env`: `DATABASE_URL` для PostgreSQL (без неё база SQLite в `~/poekhali-data/bureau.db`) и `BUREAU_PUBLIC_URL`. Обновление: `cd ~/poekhali && git pull && bash deploy/beget/install.sh`. Ограничения те же, что у Vercel: без WebSocket (опрос) и без `checker`.

### Публикация на GitHub Pages

`.github/workflows/pages.yml` при каждом push в `main` проверяет контент, гоняет Vitest и собирает игру с `BUREAU_BASE=/<имя репозитория>/`. Локально: `BUREAU_BASE=/poekhali/ npm run build` (в Git Bash на Windows — с `MSYS_NO_PATHCONV=1`).

## Разработка

```bash
cd server && python -m bureau_server --port 8000   # сервер урока (API + WebSocket)
cd frontend && npm run dev                          # http://localhost:5173, /api и /ws проксируются на :8000
```

Без сервера игра работает в режиме «Самостоятельно». Служебные адреса: `/#/teacher` — пульт урока, `/#/present` — проектор, `/#/plan/0` — план урока, `/#/print/0` — печатные материалы, `/#/experts` — страница для экспертов, `/#/art` — галерея графики, `/#/checks` — все типы проверок, `/#/style` — пробник стиля.

Серверная проверка при разработке: `BUREAU_LOCAL_CHECK=1 python -m bureau_server` (изолированный процесс рядом с сервером; только для разработки).

## Тесты

```bash
python -m pip install pytest httpx fastapi "uvicorn[standard]"
python -m pytest -q packages/judge/tests tools/tests server/tests   # судья, линтер, контент, сервер урока
python tools/lint_content.py                                         # линтер контента
cd frontend && npm test                                              # Vitest
cd frontend && npm run build                                         # типы и сборка
cd frontend && npm run test:identity                                 # судья в CPython и Pyodide побайтово равен
cd frontend && npm run build && npm run test:e2e                     # Playwright в установленном Chrome: урок, экипаж, опрос, проектор, вёрстка
cd frontend && node scripts/ui-audit.mjs http://localhost:8010 <пароль> ui-audit   # аудит вёрстки всех экранов (сервер урока запущен)
```

## Структура

- `packages/judge` — судья заданий (чистый Python): песочница, кейсы и замечания заказчика, AST-правила, стиль, оценка, переводчик ошибок, трассировщик, детекторы багов
- `server/bureau_server` — сервер урока: коды урока, пароль преподавателя, этапы, «Внимание!», панель класса, опросы, код учеников и комментарии, отчёт CSV (FastAPI + WebSocket + SQLite); `checker.py` — изолированная проверка кода (сервис для Docker)
- `server/Dockerfile`, `docker-compose.yml` — развёртывание: сервер урока + checker
- `tools/lint_content.py` — линтер контента: правила «воздуха», навыки, allowed_constructs, автотест заданий, музей
- `content/` — занятие, сцены, задания, персонажи, навыки, глоссарий, музей
- `frontend/` — React + Vite + CodeMirror + Framer Motion; Pyodide в Web Worker; игра в `src/game`, слой урока в `src/lesson`, пульт в `src/teacher`, движок сценария в `src/dialogue`, SVG-графика в `src/art`
- `docs/` — мир (`world.md`), факты с источниками (`space-facts.md`), решения, схема контента, тексты на ревью, руководство преподавателя
- `PROMPT.md` — полное ТЗ, `CONTEXT.md` — текущее состояние, `CLAUDE.md` — правила разработки
