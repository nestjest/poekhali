# Схема контента курса «Поехали!»

Сеттинг, персонажи, локации и словарь — `docs/world.md`. Факты — только из `docs/space-facts.md`.

Весь контент — JSON в `/content` (решение: без YAML, чтобы судья и линтер оставались без зависимостей, а браузер читал те же файлы). Проверка: `python tools/lint_content.py`.

## Файлы

```
content/
  characters.json        персонажи: сотрудники бюро (staff) и заказчики (client)
  skills.json            навыки (граф зависимостей)
  glossary.json          словарь терминов «простыми словами»
  report_phrases.json    шаблонные фразы отчёта «что сделал / как проверил»
  lessons/lesson0.json   занятие: цель, этапы, тетрадь, рефлексия, подсказки преподавателю
  dialogues/<id>.json    диалоги (планёрка, код-ревью, диагностика)
  orders/<id>.json       задания (id файла: o0-1, o0-2 … o0-boss)
  museum.json            экспонаты «Музея бюро» (факт + условие открытия + вопросы quiz)
  quotes.json            «Цитата дня» в конце смены (ФИО, годы, чем занимался, источник)
  crews/<id>.json        командная программа «Конца смены» + музейный опрос экипажа
```

## characters.json
`{ "vika": {"name": "Вика", "role": "staff", "about": "ведущий инженер бортового ПО, наставник"}, "zoya": {"name": "Зоя Андреевна", "role": "client", "business": "школьный кружок «Юный космонавт», кубсат «Искорка»", "voice": "увлечённо, по-учительски, называет игрока «коллега»"} … }`
Допустимые id (для них есть SVG): olga, vika, max, gromov (сотрудники); zoya, sokolov, kira, tamara, fedor, ilya (заказчики). `role` — только `staff` или `client` (линтер).

## skills.json
`[{"id": "print", "title": "Вывод print()", "lesson": 0, "requires": []}, {"id": "variables", "title": "Переменные", "lesson": 0, "requires": ["print"]} …]` — граф без циклов.

## glossary.json
`[{"term": "переменная", "forms": ["переменной", "переменную", "переменные"], "simple": "Коробка с наклейкой-именем, в которой лежит значение.", "example": "name = \"Нина\"", "lesson": 0}]`
В текстах термин отмечается `[[переменная]]` или `[[переменную|переменная]]` (форма слова | термин): в интерфейсе он становится кнопкой с пояснением. Не больше одного **нового** термина на реплику.

## Правила текста (линтер)
- Реплика (`say.text`, `pitch[i]`, ответы клиента, feedback, complaint/approve, hint) — ≤ 35 слов.
- Абзац (разделитель `\n`) — ≤ 2 предложений. Код в тексте — в обратных кавычках `` `print(name)` `` (считается одним словом).
- Не больше 4 реплик `say` подряд без `check`.
- Тон: коротко, тепло, с лёгким юмором; ошибки объясняют, не ругают. Макс делает типичные ошибки новичка.

## Диалог — dialogues/<id>.json
```json
{"id": "l0-briefing", "lesson": 0, "review_needed": true, "diagnostic": false, "nodes": [
  {"id": "n1", "type": "say", "who": "vika", "mood": "joy", "text": "Привет! Сегодня первый рабочий день."},
  {"id": "n2", "type": "check", "check": {…}},
  {"id": "n3", "type": "choice", "options": [{"text": "Понятно", "next": "n5"}, {"text": "Объясни ещё раз", "next": "n4"}]},
  {"id": "n4", "type": "say", "who": "vika", "mood": "thinking", "text": "…", "next": "n5"},
  {"id": "n6", "type": "flag", "set": "met_max"},
  {"id": "n9", "type": "end"}
]}
```
Узлы идут по порядку; `next` — явный переход. `mood`: neutral | joy | puzzled | annoyed | thinking.
`diagnostic: true` — диагностика (проверки не вводят навыков и не требуют их).

### Проверка (check) — общие поля
`kind, prompt, requires[], introduces[], hint, explain (текст для «Не знаю — объясни»), feedback_correct, feedback_wrong`.

| kind | поля |
|---|---|
| single | `options[]`, `answer`: индекс |
| multi | `options[]`, `answer`: [индексы] |
| predict | `code` (строка или массив строк), `stdin[]` (опц.). Верный ответ = реальный вывод кода |
| order | `lines[]` — строки в ВЕРНОМ порядке (интерфейс перемешает) |
| fill | `code` с пропусками `{{0}}`, `{{1}}`; `chips[]`; `answer`: [индекс чипа для каждого пропуска] |
| find_bug | `code` (массив строк), `answer`: номер строки с ошибкой (с 1) |
| tiny_code | `starter`, `reference`, `expected_stdout[]`, `stdin[]` (опц.) |
| match | `pairs`: [["слева", "справа"], …] |

## Заказ — orders/<id>.json
```json
{
  "id": "0.2", "lesson": 0, "order_no": 2, "kind": "regular", "client_id": "nina",
  "title": "Приветствие по имени",
  "pitch": ["Милый мой, хочу, чтобы касса здоровалась с покупателем.", "…"],
  "clarify": {
    "prompt": "Что уточнить у Нины Петровны?",
    "options": [
      {"text": "Откуда программа узнает имя?", "relevant": true, "reply": "Покупатель сам введёт.", "adds_requirement": "R2"},
      {"text": "Каким шрифтом печатать?", "relevant": false, "reply": "Ох, милый, у кассы один шрифт — какой есть!"}
    ]
  },
  "requirements": [{"id": "R1", "text": "Программа спрашивает имя"}, {"id": "R2", "text": "…"}],
  "statement_md": "Короткое ТЗ (1–3 предложения).",
  "scaffold_level": 2,
  "parsons_lines": [{"code": "name = input()"}, {"code": "print(\"Здравствуйте,\", name)"}, {"code": "print(Здравствуйте, name)", "distractor": true}],
  "fill_code": ["name = ___", "print(\"Здравствуйте,\", ___)"],
  "starter_code": ["# Спроси имя и поздоровайся"],
  "cases": [
    {"id": "c1", "stdin": ["Оля"], "expected_stdout": ["Здравствуйте, Оля"], "hidden": false, "weight": 1,
     "requirement_id": "R2", "approve": "Ой, поздоровалась!", "complaint": "Покупательница Оля ждала приветствия, а касса молчит."},
    {"id": "h1", "stdin": ["Анна-Мария"], "expected_stdout": ["Здравствуйте, Анна-Мария"], "hidden": true, "weight": 1,
     "requirement_id": "R2", "approve": "…", "complaint": "Анна-Мария пришла — а касса её не узнала."}
  ],
  "ast_rules": {"require": ["Call:input"], "forbid": [{"rule": "Str:Здравствуйте, Оля", "max": 0}]},
  "hints": ["где искать", "какая конструкция нужна", "пример на соседней задаче — БЕЗ готового решения"],
  "requires": ["print", "variables"], "introduces": ["input"],
  "reference_solution": ["name = input()", "print(\"Здравствуйте,\", name)"],
  "rewards": {"tips": {"3": 10, "4": 15, "5": 25}},
  "review_needed": true
}
```
- `scaffold_level`: 1 — Parsons (`parsons_lines`, лишние строки помечены `distractor`), 2 — пропуски (`fill_code` с `___`), 3 — «напиши сам» (`starter_code`). Студент может спуститься на ступень ниже, если поля для неё есть.
- `kind` bugreport/refactor: `starter_code` — готовый код с багом / под доработку, `scaffold_level: 3`.
- Подсказки ввода `input("…")` **не попадают** в вывод: в `expected_stdout` их нет.
- Обязательные условия (линтер): эталон 5★ на всех кейсах при 0 подсказок и точном уточнении; эталон соблюдает стиль PEP 8 (пробелы вокруг `=`, после запятой); шаблоны проваливают хотя бы один кейс; у каждого скрытого кейса есть `complaint` и `requirement_id`; подсказки не содержат строк эталона длиннее 12 символов; не меньше одного скрытого кейса.
- `warmup` (опц.) — проверка (`check`) перед сборкой кода, например predict для заказа 0.1.

## Игровые узлы сценария (визуальная новелла, от первого лица)

Игрок — «я». Его реплики — это **варианты выбора** (`choice.options[].text`) или `say` с `"who": "player"`. Узлы без ожидания игрока применяются автоматически.

| type | поля | что делает |
|---|---|---|
| scene | `location`: street (проходная) \| reception (бюро пропусков) \| board (класс подготовки) \| desk (рабочее место) \| counter (окно заданий) \| studio (зал бюро) \| launch (стартовый стол); `time`: morning \| day \| evening; `cast`: [{`who`, `pos`: left\|center\|right, `mood`}]; `transition`: fade \| zoom \| slide; `title` (титр, напр. «Понедельник, 9:00») | Смена локации, состав персонажей в кадре, доска очищается |
| enter / exit | `who`, `pos`, `mood` | Персонаж входит в кадр / уходит |
| narrate | `text` | Текст рассказчика (мысли героя, описание), курсивом, без имени |
| say | `who` (персонаж или `player`), `mood`, `text` | Реплика; настроение говорящего в кадре меняется |
| choice | `prompt` (опц.), `options`: [{`text`, `next` (опц.)}] | Ответ игрока. Без `next` — идём дальше по порядку. Варианты могут сходиться |
| board | `title`, `lines` (≤ 6 строк, ≤ 14 слов в строке; код в обратных кавычках; `[]` — стереть) | Конспект на доске: остаётся на экране, пока идут реплики |
| input | `field`: nick \| group, `prompt` | Игрок вписывает псевдоним / код группы (в пропуск). В режиме урока `group` берётся из урока и узел пропускается |
| avatar | `prompt` | Игрок выбирает фото для пропуска |
| unlock | `feature`: phone, notebook, vika_chat, mail, reviews, shop, skills, settings, studio, desk, orders, board, door, coins, museum, orbit; `text` | Открывает функцию (всплывающее «Новое: …») |
| crew | `mission` (id из `content/crews`, той же `lesson`) | Командная программа «Конца смены»: экипаж собирает программу из частей (`game/CrewMission.tsx`); узел ждёт, пока программа экипажа получит ≥ 3★. Ставится перед `launch` |
| quote | `quote` (id из `content/quotes.json`) | «Цитата дня»: карточка с цитатой, ФИО, годами жизни, чем человек занимался, и источником; кнопка «Записать в музей и домой». Ставится в конце `dN-closing` перед `flag`/`end`; показанные цитаты собираются в музее |
| launch | `craft` (название аппарата), `text` (опц., подпись) | Катсцена запуска: обратный отсчёт, старт ракеты, аппарат выходит на «Карту орбит». Только `transform`/`opacity`; при reduced motion — статичные кадры |

Ритм: не больше 4 реплик (`say`/`narrate`) подряд без `choice`, `check` или `input`. Персонажи: olga (инструктор), vika (наставник), max (стажёр), gromov (главный конструктор), заказчики — см. `docs/world.md` §4.

### Этапы занятия (поля для игры)
`{"id", "title", "dialogue" | "orders", "minutes", "hotspot": orders|desk|board|cabinet|mail|shop|reviews|door|museum|orbit, "auto": true|false, "unlocks": [...] , "teacher": {...}}`
- `auto: true` — этап запускается сам после предыдущего (вступление, диагностика).
- `hotspot` — объект зала бюро, к которому ведёт маркер цели.
- В режиме урока этап доступен, только если его открыл преподаватель (сервер, `PROMPT.md` §9); в режиме «Самостоятельно» — по порядку, как описано выше.
- `unlocks` — функции, которые открываются после этапа.

### Реплики заказчика в задании (опц.)
`"lines": {"accept": "фраза клиента, когда ТЗ понятно", "good": "прощание после принятого заказа", "revision": "просьба доработать"}`

### Вопрос заказчика по музею (опц.)
`"museum": {"exhibit": "korolev", "question": 0, "ask": "реплика заказчика (≤ 35 слов, ≤ 2 предложений)"}`
- После принятого задания (≥ 3★, без доработки) заказчик задаёт вопрос `quiz[question]` экспоната `exhibit`: ответ один раз, верный — `MUSEUM_BONUS` (10) премии. Отвечать можно, только изучив экспонат (кнопка «Открыть в музее» → «Изучить»). В «Классике» вопроса нет.
- Линтер: экспонат и вопрос существуют, экспонат уже открыт к моменту сдачи (открыт с начала, после более раннего этапа или занятия, после этого же задания или задания прошлого занятия).

## Командная программа — crews/<id>.json

Одна на занятие (`crew0`…`crew3`), вызывается узлом `crew` в сцене «Конец смены».

| поле | что это |
|---|---|
| `id`, `lesson`, `title`, `craft`, `client_id` | как у задания; `id` = имя файла |
| `brief` | 1–2 строки: что нужно заказчику (правила воздуха) |
| `parts` | 2–4 части по порядку исполнения: `id`, `role` (Оператор / Баллистик / Аналитик / Связист), `title`, `task`, `gives[]` (что передаёт дальше), `uses[]` (что получает), `template` (с `___`), `reference` |
| `requirements`, `cases` | как у задания: у скрытых кейсов `complaint` и `requirement_id` |
| `hints` | ровно 3, без строк эталона; первая — про договорённость об именах переменных |
| `requires` | навыки, введённые раньше |
| `quiz` | музейный опрос экипажа: 2–5 вопросов `{"exhibit", "question"}` по уже открытым экспонатам (экспонаты самого «Конца смены» ещё закрыты). Один ответ на экипаж; верный — `QUIZ_POINTS` (2) очка в «Гонке экипажей» (считает сервер, `/api/crew/quiz`), без урока — 5 премии |

Судья склеивает части по порядку (`judge.run_crew`; часть, которую ещё не писали, — её шаблон) и проверяет как обычное задание; строку ошибки относит к части (`error_part`). Линтер: склеенный эталон — 5★ и только `allowed_constructs`, склеенные шаблоны проваливают кейсы, миссия используется в сцене своего занятия.

Распределение частей: часть *i* пишет участник *i mod n* (в экипаже из двух первый пишет две части; четвёртый — испытатель).

## Музей бюро — museum.json
```json
[{"id": "ps1", "title": "ПС-1 — первый спутник", "year": 1957, "text": "Шар 58 см, 83,6 кг, четыре антенны.", "fact": "ps1", "unlock": "start"},
 {"id": "kedr", "title": "Позывные", "year": 1961, "text": "…", "fact": "callsigns", "unlock": {"order": "o0-5"}}]
```
- `fact` — id строки из `docs/space-facts.md` (линтер проверяет). `year` — необязателен (у физических величин даты нет). `text` — ≤ 35 слов, ≤ 2 предложений в абзаце.
- `unlock`: `"start"` | `{"stage": "<id этапа>", "lesson": N}` (после этапа занятия N; без `lesson` — занятие 0) | `{"order": "<файл задания>"}` (после принятия задания ≥ 3★ или зачёта преподавателем).
- `art` (опц.) — id рисунка экспоната: sputnik | vostok | lunokhod | station | rocket | glonass | cubesat | engine.
- `quiz` — 1–2 вопроса по тексту таблички: `{"question", "options": [3–4 варианта без повторов], "answer": номер с нуля}`. Ответ должен находиться в `text` экспоната. Вопросы используют задания (`museum`) и экипажи (`quiz`).
- Открытый экспонат показывает название; текст таблички — после «Изучить» (`museumStudied` в сохранении). Неизученные считает значок на иконке музея в телефоне.

## Цитата дня — quotes.json
```json
[{"id": "gagarin_go", "name": "Юрий Алексеевич Гагарин", "years": "1934–1968", "role": "Лётчик-космонавт, первый человек в космосе",
  "about": "Чем занимался (≤ 2 предложений).", "quote": "Поехали!", "context": "Когда и где сказано.", "fact": "quote_gagarin_go", "source": "Википедия: «Восток-1»"}]
```
- Только документальные цитаты с источником: `fact` — строка `quote_*` в `docs/space-facts.md`. `name` — фамилия, имя, отчество. Это не реплика персонажа: правило «реальные люди не произносят реплик» соблюдается.

## Тетрадь — поле `notebook` занятия
- Карточка видна в «Тетради», когда введён её навык (`skills` карточки, по умолчанию — её `id`) или пройден инструктаж (`konspekt`) этого занятия; темы будущих занятий скрыты (`src/lib/notebook.ts`). Линтер проверяет, что навыки карточки есть в `skills.json`.

## Задания: реальные данные
Числа и названия в `cases`, `pitch`, `clarify` берутся из `docs/space-facts.md` (масса ПС-1, 1440 витков, позывные «Кедр»/«Чайка», годы запусков). Вымышленные аппараты бюро («Искорка», «Облачко», «Северок», «Дозор») — по `docs/world.md`.

## Несколько занятий
- Файлы: `lessons/lessonN.json`, сцены `dN-intro`, `lN-warmup`, `dN-konspekt`, `lN-briefing`, `lN-review`, `dN-closing`, задания `oN-1 … oN-boss`.
- Этапы занятий 1–3 (id строго): `intro` (auto) → `warmup` (auto, разминка по прошлым занятиям) → `konspekt` → `briefing` → `orders` → `review` → `closing` (запуск аппарата занятия узлом `launch`).
- `allowed_constructs` в занятии N — только **новые** конструкции; линтер объединяет их с прошлыми занятиями. Занятие 1: `Attribute`, `JoinedStr`, `Call:.strip/.title/.upper/.lower/.replace/.capitalize`; 2: `If`, `Compare`, `BoolOp`, `UnaryOp`, `Call:.isdigit`; 3: `While`, `For`, `Break`, `Continue`, `Call:range`, `AugAssign`.
- Навыки и термины всех занятий заданы заранее в `skills.json` и `glossary.json` (поле `lesson`).
- Игра: текущее занятие — первое, у которого не пройден «Конец смены»; в уроке — то, что выбрал преподаватель (`src/lib/lessons.ts`).
- Параллельная работа над несколькими занятиями: `python tools/lint_content.py --assume-prev` считает навыки прошлых занятий введёнными; финальная проверка — без флага.
