# Руководство по апробации курса «Поехали!»

Документ для преподавателя или методиста: как провести апробацию в группе без участия разработчика и собрать данные для конкурсной заявки. Сам урок описан в `docs/teacher-guide.md`; здесь — что подготовить, что фиксировать и как оформить результат.

**Важно.** В репозитории нет результатов апробации. Все таблицы ниже — пустые шаблоны. Заполняйте их только реальными данными.

## 1. Подготовка

### 1.1 Сервер и сеть

1. Компьютер преподавателя: Windows/Linux/macOS, Node.js 20+, Python 3.11+.
2. Один раз соберите игру и поставьте зависимости сервера (команды — `docs/teacher-guide.md`, раздел 1; коротко: `cd frontend && npm install && npm run build`, затем `cd server && python -m pip install -r requirements.txt`).
3. Запуск: `cd server && python -m bureau_server`. В окне появятся адреса для учеников и преподавателя и пароль (показывается один раз, запишите; свой пароль — `--set-password`).
4. Сеть класса: ноутбуки учеников и компьютер преподавателя в одной сети (Wi-Fi или кабель). Интернет не нужен. Если адрес не открывается, разрешите Python в брандмауэре (частная сеть) и проверьте, что устройства не в «гостевой» сети с изоляцией клиентов.
5. Проверка за день до занятия: откройте адрес для учеников с другого устройства (телефон или ноутбук), нажмите «Войти в урок», убедитесь, что код принимается и на пульте виден ученик.
6. Окно сервера не закрывайте до конца занятия. Резерв: запустите второй экземпляр на другом компьютере.

### 1.2 Ноутбуки и браузеры

- Современный Chrome, Edge, Firefox или Яндекс Браузер последних версий; нужна поддержка WebAssembly (Pyodide).
- Первое открытие игры загружает Pyodide (десятки мегабайт из локальной сети) — откройте игру на всех ноутбуках до начала урока, чтобы кэш был готов.
- Звук не нужен. Для проектора — разрешение не ниже 1280×720.
- Резерв: 1–2 запасных устройства и режим «Самостоятельно» (работает без сервера).

### 1.3 Согласия и документы

- Студенты вводят только **псевдоним**. ФИО, e-mail, телефон игра не запрашивает и не хранит (требования 152-ФЗ «О персональных данных» соблюдаются тем, что персональных данных нет).
- Для несовершеннолетних школьников получите согласие законных представителей на участие в апробации по форме образовательной организации.
- Анкеты (раздел 5) анонимны: на бумаге без фамилий; для связки «анкета — запись в отчёте» используйте тот же псевдоним или номер, не ФИО.
- Фото-аватар в игре необязателен. Если используется — только по согласию, не в публичные материалы.
- Видео и фото урока — только с согласия, без лиц учеников в кадре, если согласия нет (см. раздел 8).

### 1.4 Что распечатать

- План занятия (`/#/plan/0` … `/#/plan/3`) и печатные материалы (`/#/print/0` … `/#/print/3`): конспект ученика, лист рефлексии, критерии и рубрика.
- Анкету SUS и короткую анкету студента (раздел 5) — по числу участников.
- Бланк наблюдения (раздел 3).

## 2. Сценарий: 4 занятия по 90 минут

Занятия 0–3 идут подряд (неделя или две). Режим урока — «Вместе с классом». Код урока создаётся на пульте для каждого занятия заново; студент входит с тем же псевдонимом.

Общая рутина каждого занятия:

1. До начала: запустить сервер, открыть `/#/teacher`, войти, «Новый урок» → выбрать занятие и группу, показать на проекторе «Код на весь экран».
2. Ученики открывают адрес, «Войти в урок», вводят код и псевдоним.
3. Преподаватель открывает этапы кнопкой «Открыть этап «…»», следит за панелью класса (статусы «Зовёт», «Застрял», «Ждёт этап»), разбирает «Частые ошибки класса».
4. В конце: «Завершить урок…» → скачать отчёт CSV **до** или сразу после завершения (отчёт доступен и после) → сохранить в папку апробации.

### Занятие 0 «Первый день в бюро» (аппарат «Искорка»), 90 мин

| Этап | Мин | Роль преподавателя на пульте |
|---|---|---|
| Первый день | 5 | Открыть этап; объяснить цель курса одной фразой; «Внимание!» не использовать |
| Входной тест (диагностика A) | 5 | Сказать «это не оценка»; напомнить «Не знаю — объясни». Фиксировать результат A по каждому ученику |
| Инструктаж у Ольги | 15 | Открыть этап; при необходимости «Внимание!» и свой комментарий у доски |
| Планёрка | 10 | Спросить класс «что Макс сделал не так?» |
| Задания 0.1–0.5, итоговое «Паспорт аппарата» | 40 | Следить за «Застрял»/«Зовёт»; подходить к зовущим и нажимать «Подошёл»; фиксировать частые ошибки; при необходимости «Зачесть задание…» |
| Разбор полётов | 10 | Разбор чужого кода у доски |
| Конец смены | 5 | Запуск «Искорки», рефлексия, домашнее задание |

### Занятие 1 «Телеметрия» («Облачко»), 90 мин

Утро 2, разминка 3, инструктаж 12, планёрка 8, задания 50 (в т. ч. refactor 1.3–1.4, bugreport 1.5, итоговое «Манифест груза»), разбор 10, конец смены 5. На пульте: после разминки сверить «долю верных ответов» по прошлому занятию; на этапе «Задания» разобрать у доски ошибки `//` и `%`.

### Занятие 2 «Связь для посёлка» («Северок»), 90 мин

Утро и разминка 5, инструктаж и планёрка 20, задания 45 (2.1–2.6, итоговое «Диспетчер связи»), командное задание 10 (2.7 «Баг-охота», группы по 2–3), разбор и рефлексия 10. На пульте: перед командным заданием объявить состав команд через «Сообщение классу»; зафиксировать, кто из учеников в какой команде.

### Занятие 3 «Лесной дозор» («Дозор»), 90 мин

Разминка 5, инструктаж и планёрка 20, задания 45 (3.1–3.7, итоговое «Сводка дозора за смену»), разбор и **перенос в IDE** 15 (скачать `.py`, запустить в Thonny/IDLE, преподаватель подтверждает), итоговый тест (диагностика B) и рефлексия 5. На пульте: подтвердить перенос в IDE каждому (отметка в бланке; в рубрике это 10 %), открыть этап итогового теста B, дождаться всех.

### После каждого занятия (10 минут)

- Сохранить отчёт CSV: `занятие_N_дата.csv`.
- Записать три частых ошибки класса с пульта.
- Выдать лист рефлексии (`/#/print/N`) — собрать на следующем занятии.
- Записать замечания к тексту, заданиям, интерфейсу (раздел 3).

## 3. Что фиксировать

| Что | Источник | Как собрать |
|---|---|---|
| Отчёт урока: этапы, ответы верно/всего, число вызовов, по каждому заданию ★, число проверок, число подсказок, принято/зачтено преподавателем | CSV с пульта (`GET /api/teacher/sessions/{id}/report.csv`, разделитель `;`, кодировка UTF-8 с BOM — открывается в Excel/LibreOffice) | Кнопка отчёта на пульте после каждого занятия |
| Журнал урока (входы, открытия этапов, «Внимание!», зачёты, вызовы, время) | `GET /api/teacher/sessions/{id}/log` | Сохранить JSON |
| Диагностика A и B, прирост | Результаты форм A (занятие 0) и B (занятие 3) по 10 вопросов; прирост = B − A | Из отчёта пульта; если в отчёте отсутствует — со скриншота итогового экрана теста; считать в таблице (раздел 6) |
| Время до первого запуска кода | Секундомер наблюдателя: от открытия задания 0.1 («Окно заданий») до первого нажатия «Запустить». Метрика из ТЗ — не более 5 минут | Бланк наблюдения: 3–5 учеников выборочно |
| Первое задание без помощи | Доля учеников, принявших задание 0.1 без подсказок и вызова преподавателя (в отчёте: подсказок = 0 и вызовов = 0). Целевое значение по ТЗ — не менее 80 % | Из CSV |
| Число вызовов преподавателя и подсказок | Столбцы «Вызовов преподавателя» и «… подсказок» отчёта | Из CSV |
| Частые ошибки | Блок «Частые ошибки класса» на пульте (теги переводчика ошибок) | Скриншот или запись в конце каждого занятия |
| Оценка преподавателя по рубрике | Итоговое задание: функциональность 50 %, отладка 20 %, стиль 10 %, самостоятельность 10 %, перенос в IDE 10 % → ≥ 85 % «5», ≥ 70 % «4», ≥ 50 % «3» | Печатная рубрика `/#/print/N`. Игровая премия на оценку не влияет |
| Технические сбои | Бланк наблюдения | Время, устройство, что произошло, как решили |
| Замечания к текстам и фактам | Бланк наблюдения | Номер сцены/задания, формулировка |

## 5. Анкеты

### 5.1 Анкета SUS (шкала удобства системы)

Отвечать сразу после занятия 3, анонимно. Шкала: 1 — «совершенно не согласен», 5 — «полностью согласен».

| № | Утверждение | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 1 | Я хотел(а) бы пользоваться этой системой часто | | | | | |
| 2 | Система показалась мне излишне сложной | | | | | |
| 3 | Система проста в использовании | | | | | |
| 4 | Мне понадобилась бы помощь технического специалиста, чтобы пользоваться системой | | | | | |
| 5 | Различные функции системы хорошо сочетаются друг с другом | | | | | |
| 6 | В системе слишком много несоответствий и противоречий | | | | | |
| 7 | Думаю, большинство людей быстро научится пользоваться этой системой | | | | | |
| 8 | Пользоваться системой было неудобно и громоздко | | | | | |
| 9 | Я чувствовал(а) себя уверенно, пользуясь системой | | | | | |
| 10 | Мне пришлось многому научиться, прежде чем я смог (смогла) начать работу | | | | | |

**Подсчёт.** Для нечётных вопросов (1, 3, 5, 7, 9) вклад = ответ − 1. Для чётных (2, 4, 6, 8, 10) вклад = 5 − ответ. Сумма вкладов × 2,5 = SUS от 0 до 100. Итог группы — среднее по участникам. Целевое значение по ТЗ — не менее 80 (ориентир, не гарантия).

### 5.2 Короткая анкета студента

Анонимно, 5 минут, после занятия 3.

1. Что тебе понравилось больше всего? (свободный ответ)
2. Что мешало или раздражало? (свободный ответ)
3. Насколько понятно, что нужно делать в задании? (1 — совсем непонятно … 5 — всегда понятно)
4. Насколько помогали подсказки Вики и замечания заказчика, чтобы найти ошибку? (1–5)
5. Игровая оболочка помогала учиться или отвлекала? (помогала / не замечал(а) / отвлекала)
6. Что из Python ты теперь можешь сделать сам(а)? (свободный ответ)
7. Был(а) ли у тебя опыт программирования до курса? (нет / немного / да)
8. Хочешь ли ты продолжать изучать Python? (да / возможно / нет)
9. Что бы ты изменил(а) в игре в первую очередь? (свободный ответ)

Для преподавателя: на листе рефлексии (`/#/print/N`) уже есть 3–4 вопроса по теме занятия — их результаты не смешивать с анкетой.

## 7. Этика и персональные данные

- Только псевдонимы. Не просите учеников вводить ФИО в игре; сервер не имеет для этого полей.
- Отчёты CSV и журнал содержат только псевдонимы и результаты. Не соединяйте их с ФИО в публичных материалах; таблицу «псевдоним — ФИО» (если нужна для выставления оценок) храните отдельно, на бумаге или в защищённом файле организации.
- Данные уроков хранятся в локальной базе SQLite на компьютере преподавателя. По окончании апробации и сбора сводки сохраните нужное и удалите файл базы (расположение — в настройках запуска сервера) по правилам вашей организации.
- Согласие законных представителей — для несовершеннолетних; участие добровольное; право отказаться без последствий для оценки.
- Игровая премия и «надёжность бюро» не влияют на отметку; отметка — по рубрике преподавателя.
- Анкеты анонимны; результаты публикуются только в агрегированном виде.

## 8. Видео до 7 минут: план съёмки

Цель — показать полный путь урока и ключевые отличия курса. Хронометраж ориентировочный, итог не более 7:00. Экранная запись + закадровый текст; лица учеников не в кадре без согласия (снимать экраны и руки, класс — общим планом со спины).

| Шаг | Время | Что в кадре | Что сказать |
|---|---|---|---|
| 1. Идея | 0:00–0:30 | Титул игры, Бюро «Космос» | Для кого курс, что осваиваем (МДК 05.04, ПК 5.8), как вписан в урок |
| 2. Запуск у преподавателя | 0:30–1:00 | Окно `python -m bureau_server`, пульт `/#/teacher`, «Новый урок», код на весь экран | Без установки у учеников, сеть класса, без интернета |
| 3. Вход учеников | 1:00–1:25 | «Войти в урок», «кедр 42» (грязный ввод), псевдоним | Только псевдоним, 152-ФЗ |
| 4. Управление темпом | 1:25–2:10 | «Ждём команду ЦУП» → открытие этапа на пульте → игра идёт дальше; «Внимание!» | Студент не проходит дальше открытого этапа |
| 5. Теория и диагностика | 2:10–2:50 | Ольга у доски, облачко диалога, проверки (показать 2–3 типа, «Не знаю — объясни»), входной тест | Теория по шагам, безопасность |
| 6. Цикл задания ①–④ | 2:50–4:40 | Брифинг → IDE: Parsons → пропуски → «сам» → испытания → замечание заказчика по скрытому тесту → доработка v1.1 → ★ и запуск | Практика, ступени поддержки, скрытые кейсы, отладка |
| 7. Разнообразие | 4:40–5:20 | Фрагменты bugreport, refactor, командное 2.7, итоговое | Виды заданий |

| 9. Адаптивность и доступность | 6:00–6:30 | Телефон (360 px), тёмная тема, A+, «читаемый шрифт», «Классика» | Единый стиль, доступность |
| 10. Итог | 6:30–7:00 | «Карта орбит» с запущенными аппаратами, страница `/#/experts` | Как проверить ресурс, ссылка |

Подготовка к съёмке: заранее создать урок и ввести 2–3 тестовых псевдонима (например «Кедр», «Чайка», «Орёл»), проверить, что все окна на русском, убрать лишние вкладки и уведомления; запись в Full HD; текст озвучки репетировать с секундомером.
